# 路线图

当前是 **v0.3.3**：WebSocket 双向桥、多令牌、多设备、发送/回传队列、面板页签和本机安装都已可用。下面是后续方向，按优先级排列。

## P0：正确性 / 可靠性

- [x] ~~**通知重试队列**~~（0.3）：DSH 侧发送队列（50 条 / 10 分钟）+ `ack` 确认，重连按 `msgId` 幂等补发。
- [x] ~~**回复失败重试**~~（0.3）：`reply` / `reply-result` + 离线队列 + 重试 3 次，失败记 `dsh-notify.reply-failed`。
- [x] ~~**多会话相关性**~~（0.3）：回复窗口绑定 `deviceId + sessionId`，多设备不串；正文按 `deviceInText` 标设备。
- [ ] **队列持久化**：发送队列、回传队列、`msgId` 去重表都在内存，Coopanion/DSH 重启即丢。可以落到 `dataDir` 下的小文件，配合已有幂等键重放。
- [ ] **多条通知排队**：仍然只保留最新一条通知的回复窗口；改成有限队列或按设备各留一个窗口，避免「刚说完 A 的提示，B 的提示把窗口顶掉」。
- [ ] **背压用例**：服务端已按 `bufferedAmount` 保护，但没有测试覆盖大积压。

## P1：配置与使用体验

- [ ] **预设**：把「关键字 / 窗口 / 两者都要」做成带说明的预设。
- [ ] **面板 i18n**：面板目前硬编码中文；Cortico 支持 `ctx.language`。
- [ ] **面板表单校验**：端口范围、`ws://` 格式、关键字为空、窗口为 0 的即时提示。
- [ ] **令牌管理增强**：过期时间、按设备吊销（现在是一令牌可多设备）、令牌使用统计。
- [ ] **状态页**：World 页显示待回复窗口、队列长度、最近错误（现在靠 `dsh_notify_status` 与「设备」页签）。
- [ ] **DSH 配置卡片显示连接状态**：Client 半目前只能渲染表单，拿不到 Host 侧状态；需要框架提供通道或改用只读接口。

## P2：协议与安全

- [ ] **速率限制可配**：现在是每设备 30 条/分钟（10 秒 60 帧）的固定值。
- [ ] **TLS 内置**：现在靠 `wss://` + 反代/隧道；可选地在 World 里直接加载证书。
- [ ] **多客户端类型**：`hello.client` 已留字段（现在只认 `dsh`），其他 app 接入需要再定义各自的事件与回复语义。
- [ ] **消息类型扩展**：图片/语音/附件要么明确拒绝，要么设计独立上传协议（现在只转发文本）。
- [ ] **请求签名**：Bearer 之外可选 HMAC + nonce，防重放（现在靠 TLS 与令牌哈希）。

## P3：分发与工程化

- [ ] **发布到 npm**（如果决定公开）：本包仍是本地 link / `private`；发布前按 `AGENTS.md` 跑 `check:extension`、补 CHANGELOG、tags、`os` 字段。
- [ ] **CI**：GitHub Actions（Node 22、pnpm 11，两个仓库分别 test/typecheck/build/describe）。
- [ ] **端到端测试脚本化**：0.3 的验收用临时探针完成（握手/ack/去重/吊销/回传闭环），可以固化成 `scripts/e2e.mjs` 常驻仓库。
- [ ] **面板的浏览器测试**：面板 bundle 目前只通过 typecheck/manifest/HTTP 验证。
- [ ] **版本兼容矩阵**：记录 Coopanion/Cortico/DSH 版本、`cortico.api` 与协议版本的对应关系。

## 非目标

- 不做公网中继/账号系统；跨公网由用户自己准备 VPN/隧道/HTTPS 反代。
- 不读取 Coopanion 的记忆、聊天全文或 DSH 的会话全文；只传任务元数据和摘要。
- 不在通知路径上执行任意工具/命令；回复只是注入一条用户消息。
- 不自动发布到 npm；是否发布由维护者决定。
